6,7 Fine tuning pre trained models for Image Classification using Pytorch Image Models (timm)

You dont create CNNs from scratch, you use pre trained models and finetune them to your dataset (also called transfer learning). This is much faster(both training and inference), takes less data, and lowers the bar in terms of needed expertise.
timm has 700+ pre trained models, many SOTA

How to choose a model for classification:
In general prefer models in the following families; convnext, vit, swin (and v2) and EfficientNet (and v2).
(BTW resnets are in a lot of tutorials but should be avoided since they are outperformed by the above model catagories)
  • Accuracy paramount? Generally use a larger model
  • Speed/inference time paramount or running on edge device? Use a smaller model
  • Dataset very different from training dataset? Use a smaller model like vit_small_patch or conv_next_tiny
Larger models are more accurate but take longer to train, are slower, and require more memory and compute. Smaller models are less accurate but faster.

Also make sure you set pretrained=True when you create the model for fine tuning. Otherwise you have to train the model from scratch.

How Models Train at Scale on multiple GPUs An excellent, high level overview
  • Distributed Data Parallelism (DDP): For multiple GPUs, one copy of the model per GPU. Send different batches through each GPU, gather and average gradients, and apply averaged gradients to all models. (Useful only if the entire model fits on each GPU.)
  • Pipeline Parallelism: Distributes model layers across GPUs so different GPUs process different layer chunks for the same batch. Most GPUs are active simultaneously, but this can incur high communication overhead between GPUs.
  • Tensor Parallelism: Splits individual tensor operations (e.g., large matrix multiplications) across multiple GPUs.
Can combine, use Pipeline and Tensor Parallelism to create a cluster holding 1 copy of a model. Create multiple copies of this cluster. Using DDP principles, Send different batches through each of these clustered models. Gather and average gradients, apply averaged gradients to all clustered models.

15 RAG improvement-Fine Tuning Hugging Face Embedding Models

  • When to Fine-Tune Embedding Models: Fine-tune when your domain is specialized (e.g., legal, medical) and you have, or can generate, a labeled dataset. This helps the model better capture domain-specific semantics.
  • Risks of Fine-Tuning: Be aware of catastrophic forgetting, where the model loses its general knowledge while adapting to the new domain. To mitigate this, consider techniques like gradual unfreezing, using a smaller learning rate.
  • Loss Functions: Common loss functions for fine-tuning embedding models include Multiple Negatives Ranking Loss (MNRL) and Triplet Loss. These losses help the model learn to distinguish between similar and dissimilar pairs effectively.
  • Hard Negative Mining: This technique involves selecting challenging negative samples that are close to the positive samples in the embedding space. It helps improve the model's discriminative ability by forcing it to learn finer distinctions.
  • Using Hugging Face Trainer: The Hugging Face Trainer class provides a convenient way to fine-tune embedding models. It handles training loops, evaluation, and logging, making it easier to implement fine-tuning workflows.
